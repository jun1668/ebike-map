# 技术架构

## 选型

**原生微信小程序 + 云开发（CloudBase）**。

理由：
- 零服务器、零域名备案，个人主体也能直接跑起来
- 定位、地图、选点、内容安全都是微信原生能力，云函数直接调 `cloud.openapi`
- 数据量在万级以内，云开发免费额度够用很久

不用 uni-app/Taro：这个应用只有微信一个端，跨端框架反而在云开发和定位权限上多一层坑。

## 数据模型

集合 `spots`：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `brand` | string | 品牌 key，如 `hello`；自定义品牌为 `other` |
| `brandName` | string | 展示名，如「哈啰出行」 |
| `province` / `city` / `district` | string | 行政区，来自 region picker |
| `address` | string | 地址文本，来自 `chooseLocation().name` |
| `remark` | string | 备注，≤120 字 |
| `location` | GeoPoint | **地理索引字段**，geoNear 依赖它 |
| `latitude` / `longitude` | number | 数值冗余，前端直接用，避免每次拆 GeoPoint |
| `appId` | string | 可选，目标品牌小程序 AppID |
| `link` | string | 可选，用户贴的小程序链接（短链 / `#小程序://` / 网页链接），≤200 字 |
| `images` | string[] | 云存储 fileID，≤3 |
| `status` | string | `approved` / `pending` / `rejected` / `hidden` |
| `reportCount` | number | 举报计数，≥3 自动 hidden |
| `reporters` | string[] | 举报过的 openid，防重复计数（不返回给前端） |
| `upCount` | number | 预留：还在吗的投票 |
| `seeded` | boolean | 示例数据标记，便于一键清理 |
| `_openid` | string | 上传者 |
| `createdAt` / `updatedAt` | number | 毫秒时间戳 |

**必要索引**（云开发控制台 → 数据库 → 索引管理）：

1. `location` —— 类型选「地理位置」，**不加这个索引 geoNear 会直接报错**
2. `status`
3. `province`
4. `brand`
5. `_openid`
6. `createdAt`

## 云函数接口

统一返回 `{ ok: true, data }` 或 `{ ok: false, code, msg }`，前端 `utils/cloud.js` 负责拆包。

### spotList
```js
// 列表
{ page: 0, pageSize: 15, keyword: '', province: '', brand: '', latitude, longitude, radius }
// 详情
{ id: 'xxx' }
```
- 有关键词时用 `_.or` 匹配 brandName/city/province/address，**此时不走地理查询**（geoNear 与 or 组合会失效）
- 无省份、无关键词、有坐标时才用 `_.geoNear`，并把距离算好回传

### spotSubmit
```js
// 新增
{ brand, brandName, latitude, longitude, address, province, city, district, remark, appId, link, images }
// 修改
{ mode: 'update', id, remark?, address?, latitude?, longitude? }
// 删除
{ mode: 'delete', id }
```
- openid 从 `cloud.getWXContext()` 取，前端传不进来
- 内容安全：`cloud.openapi.security.msgSecCheck({ version: 2, scene: 2, openid })`，**需要在 `config.json` 里声明 `security.msgSecCheck` 权限**
- 接口异常时放行（记日志），避免微信接口波动导致整站无法上传

### spotFav
```js
{ action: 'toggle', spotId }   // → { fav: true|false }
{ action: 'list' }             // → { list: [...], total }
{ action: 'remove', spotId }   // → { removed: true }
```
- 集合 `favorites`，字段：`_openid / spotId / brand / brandName / city / district / address / latitude / longitude / createdAt`
- **存快照不存引用**：原点位被删后收藏仍能显示，`list` 会顺带查 `spots` 标注 `alive: false`
- 上限 200 条；集合不存在时 `list` 返回空数组而不是报错

### spotReport
`{ id, reason? }` → 同一 openid 只计一次；达到阈值改 `status = 'hidden'`

### spotMine
无参 → 返回当前 openid 的全部上传（含 pending）

### spotInit
`{ action: 'init' | 'seed' | 'clearSeed' | 'stats' }`

### geoReverse
`{ latitude, longitude }` → `{ province, city, district, address }`
需要环境变量 `TENCENT_MAP_KEY`；没配时返回 `{ configured: false }`，前端自动降级为「已定位 · 附近」。

## 关键设计取舍

### 1. 能不能直接跳转别人的小程序？——这是整个产品的命门

可以，但**必须拿到目标小程序的 AppID**：

```js
wx.navigateToMiniProgram({ appId: '目标品牌AppID', path: '' })
```

`path` 可以留空（进首页）。品牌官方 AppID 不在公开接口里，只能：

1. 微信里打开该品牌小程序 → 右上角「…」→ 关于 → 里面写着 AppID
2. 或让品牌的商务/运营提供

拿到后填进两处之一：
- `miniprogram/utils/link.js`：统一的链接识别与打开入口（`parseLink` / `openLabel` / `openSpot`）
- `pages/cities/cities`：城市索引（`spotList` 的 `action: 'cities'`）
- `pages/city/city`：单城市聚合（`spotList` 的 `action: 'city'`）
- `pages/mine/mine`：我的上传 / 我收藏的（顶部段控切换，收藏走 `spotFav`）
- `miniprogram/utils/brands.js` 的 `appId` 字段（全站生效，推荐）
- 用户上传时填的 `appId`（单条生效）

**所以产品做了降级路径**：没有 AppID 时按钮变成「复制名称去搜索」，弹出说明并复制品牌名，用户粘到微信首页搜索即可。功能不中断，只是多一步。

> 真机上如果目标小程序未开放跳转，`navigateToMiniProgram` 会 fail，代码里已兜底（弹提示 + 复制名称）。

### 2. 为什么用 region picker 而不是自己维护省市区数据

`<picker mode="region">` 是微信内置的全国省市区数据，零维护、永不缺城市。只有「按省份筛选的列表」需要省级名称，34 条写在 `utils/province.js` 里。

逆地理（坐标 → 城市名）才是稀缺能力，所以单独做成可选的 `geoReverse`。

### 3. 数据库权限

前端**不直接读数据库**，全部通过云函数（云函数是管理员权限，绕过权限设置）。

所以集合权限设为「**所有用户不可读写**」最安全——攻击面只剩云函数入参校验。

### 4. 内容安全是审核硬门槛

微信对 UGC 小程序的审核要求：有内容安全检测机制 + 举报入口 + 处理流程。三样都做了：

- 提交时 `msgSecCheck` 拦截
- 每条内容都有举报入口，3 次自动下架
- `about` 页写明数据来源与处理方式

## 已知限制

- 列表分页用 `skip`，数据量超过几千条后会变慢；到那时应改成按 `updatedAt` 游标分页
- `geoNear` 单次查询上限 1000 条返回（云开发查询限制），对「附近 30km」够用
- 地图 marker 一次最多渲染 200 个（`syncMarkers` 里已截断），再多应该做聚合
- 品牌 AppID 需要人工维护，短期无法自动化
