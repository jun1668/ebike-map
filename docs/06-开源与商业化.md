# 开源、版权与商业化

这份文档回答四个问题：能不能开源、版权归谁、开源了还能不能赚钱、GitHub 对上线有没有帮助。

---

## 一、能不能开源

能。这个项目的代码是自己写的：原生小程序、云函数、手绘图标，**没有引入任何第三方运行时依赖**，不存在「拿别人的代码来开源」的问题。

开源前需要确认三件事，本项目都已经处理好了：

| 检查项 | 状态 |
| --- | --- |
| AppID | `project.config.json` 里是占位符 `TOURISTAPPID`，没有你的真实 AppID |
| 云开发环境 ID | `miniprogram/utils/config.js` 里是 `YOUR_CLOUD_ENV_ID` |
| 第三方密钥 | 腾讯地图 Key 走云函数环境变量，代码里只有 `process.env.TENCENT_MAP_KEY` |

`.gitignore` 已经挡掉了 `private.*.key`、`.env`、`project.private.config.json` 和 `node_modules`。**唯一要你自己盯住的是上传密钥**——那个文件泄露，别人就能以你的身份发布小程序版本。

## 二、版权归谁

归你。理由是：著作权自作品完成之日起自动产生，不需要登记；这个项目是你提出需求、主导方向、承担风险的产出物。

有几件事要说清楚，避免以后跟人合作时被绕进去：

### 1. 著作权和「开源」是两回事

开源不是放弃版权，是**你在版权之上给别人的一份授权**。你仍然是著作权人，只是承诺「这几种用法我允许，不用另外问我」。

所以「我开源了，是不是就没版权了」——不是。版权一直在你手上。

### 2. 什么不受版权保护

- **想法**： 「做个共享电动车地图」这个点子，不受保护，谁都能做
- **功能**： 定位、上传、聚合、跳转，这些功能本身不构成作品
- **数据**： 用户上传的点位数据，单个数据不构成作品，但**汇编起来的数据集合**可以作为汇编作品主张权利

真正受保护的是：**你写下的这堆代码的具体表达**。

### 3. 商标是另一条线

「全国共享电动车」这个名字：

- 含「全国」这种地域性、描述性词汇，商标注册大概率被驳回（《商标法》第十一条：缺乏显著特征）
- 作为小程序名称也可能被微信审核打回，理由同上

要长期做，建议起一个能注册的名字（比如 `电车地图` / `小电驴在哪`），代码里的文案再统一改一遍。

### 4. 想更硬一点，去做软著登记

中国版权保护中心可以登记计算机软件著作权，几百块、一个月左右出证。

登记不是取得版权的前提（版权本来就有），但它在两件事上很有用：

- 跟人谈合作、谈投资时，有张证书比口头说「这是我写的」有力
- 真出现侵权纠纷，登记证书是初步证据

个人可以申请，不需要公司。

## 三、开源了还能赚钱吗

能，但**钱不从代码来**。这一点想清楚，后面很多决策就顺了。

### 开源不会断掉的三条收入路

**① 流量主广告（最现实，门槛最低）**

微信小程序累计独立访客达到 1000 就能开通流量主，个人主体也可以。开通后在页面里放 banner / 激励视频 / 插屏，按曝光和点击分成。

这个场景的实话：用户打开是为了「马上找到车」，停留时间短、翻页少，**广告收益不会高**。它更像是「覆盖服务器成本」级别，不是「养活项目」级别。真要靠它，得有稳定的日活。

**② 品牌合作（上限最高）**

美团、哈啰、青桔这类头部品牌不会找个人合作。真正的机会在**区域性中小共享电单车运营商**——他们在获客上很吃力，一个能把自己品牌展示给「刚到这座城市的人」的入口，对他们是有价值的。

可谈的形式：按点击结算、按新用户注册结算（CPS）、或者包月展示位。

⚠️ 注意微信规则：小程序里**不能自己接第三方广告位**（要走微信广告平台），也不能做诱导分享、诱导关注。合作形式要设计得合规，比如「官方合作品牌」展示位，而不是「点这里给你返现」。

**③ 数据与运营本身**

一个覆盖几百个城市的「哪个城市有什么共享电单车」的数据库，本身就是稀缺资产。它可以变成：

- 一份对外发布的行业观察（带来源引用的公开报告）
- 与其他出行类产品的内容合作
- 你个人在这个赛道里的背书（这个常常比直接收入更值钱）

### 开源真正会损失的是什么

**先发优势**。别人 fork 一份，一周就能上线一个一模一样的。

但反过来想：他拿到的是代码，拿不到的是你积累的**点位数据**和**已经上线的账号**。小程序这个生态里，数据量和审核历史是有复利的东西，代码不是。

所以结论是：**代码可以开源，数据留在自己服务器上**。这一点本项目天然成立——数据在云开发数据库里，不在仓库里。

### 如果不想让别人拿去商用

把 `LICENSE` 换成 **AGPL-3.0**：任何人修改后对外提供服务，必须同样开源。想闭源商用就得找你单独授权——这就是「双许可」模式，很多基础设施项目靠这个赚钱。

对比一下：

| 许可证 | 别人能商用吗 | 能闭源改吗 | 适合什么心态 |
| --- | --- | --- | --- |
| **MIT**（当前） | 能 | 能 | 想让人用、想积累口碑、不指望代码赚钱 |
| **Apache-2.0** | 能 | 能 | 同上，但多了专利授权和商标保护条款 |
| **AGPL-3.0** | 要开源 | 不能 | 想保留商业授权的谈判空间 |

换许可证只需要改 `LICENSE` 文件一个地方。

## 四、传到 GitHub 对上线有帮助吗

**有，但帮助在「以后」，不在「第一次」。**

### 第一次上线，GitHub 帮不上

第一次必须手动做一遍，绕不开：

1. 微信公众平台注册小程序，拿到 AppID
2. 开通云开发，拿到环境 ID
3. 下载开发者工具，导入项目，上传云函数
4. 真机预览，确认定位和地图正常
5. 提交审核

GitHub 在这一步只是「代码存哪儿」的问题。

### 但之后会明显省事

配上 CI 之后（`.github/workflows/upload.yml` 已经写好），日常变成：

```bash
git tag v0.1.1 && git push origin v0.1.1
```

推完自动做三件事：跑结构自查 → 跑云函数业务测试 → 上传体验版。手机微信里直接就能打开体验版看，不用碰电脑。

需要配两个 Secret（仓库 Settings → Secrets and variables → Actions）：

- `WX_APPID`：小程序 AppID
- `WX_PRIVATE_KEY`：微信公众平台 → 开发 → 开发设置 → 小程序代码上传 → 生成密钥，下载后把文件内容整个贴进去

### 还有两个隐性好处

- **版本可追溯**：哪次改动引入了 bug，`git log` 一翻就知道，比「我记得上周还好好的」强得多
- **协作与背书**：别人要给你提建议、报 bug、甚至想合作，有仓库比发压缩包专业得多

## 五、上传前最后确认清单

```bash
cd ebike-map
git init
git add .
git status          # 看一眼有没有不小心加进去的 key / 环境 ID
git commit -m "init: 共享电动车地图"
```

`git status` 那一步不要跳过。确认列表里没有：

- `private.*.key`
- `.env` 或任何含密钥的文件
- 你的真实 AppID（如果是 `TOURISTAPPID` 就没事）
- `node_modules`

然后到 GitHub 新建仓库，**选 Public**，不要勾「Add a license」（本地已经有 `LICENSE` 了，勾了会冲突）。

推上去之后：

```bash
git remote add origin git@github.com:你的用户名/ebike-map.git
git branch -M main
git push -u origin main
```

## 一句话总结

代码开源、数据自留、名字换掉、软著登记。钱的来源是「覆盖城市的数据库 + 已经跑起来的账号」，不是这堆代码本身。
