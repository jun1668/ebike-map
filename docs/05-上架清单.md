# 上架清单（照着做，从上往下）

代码写完了 ≠ 能上架。下面是**只有你能做**的动作，按顺序来，卡在哪一步就先解决哪一步。

---

## 一、先定三件事（定了再做，改起来很麻烦）

### 1. 小程序名称 —— 「附近共享电鸡」

这个名字比原来的「全国共享电动车」稳得多：

| 检查项 | 结论 |
| --- | --- |
| 地域限定词 | 「附近」是方位词，不是「全国/中国/国家」这类需资质的限定词 ✅ |
| 行业通用词 | 「共享」不构成独占，可用 ✅ |
| 撞名风险 | 「电鸡」是粤语区对电动自行车的俗称，全国范围重名概率低 ✅ |
| 潜在风险 | 「鸡」字在机器审核里偶有被误判为低俗用语的可能，属于小概率 ⚠️ |

**结论：通过概率高，但提交时仍备两个退路**，万一被驳（个人主体一年只能改 2 次名，要省着用）：

| 备选名 | 说明 |
| --- | --- |
| 附近电驴 | 「电驴」同为俗称、无歧义字，最稳 |
| 电鸡地图 | 保留辨识度，去掉「附近」显得更利落 |

原名「全国共享电动车」的问题记录在案：**「全国」属于需资质的地域限定词**，个人主体提交必拒，所以改掉是对的。

### 2. 服务类目 —— 选「工具」，别选「出行/租赁」

| 类目 | 能不能选 | 原因 |
| --- | --- | --- |
| 工具 → 信息查询 | ✅ 首选 | 你的产品本质是「查哪里有车」，不提供租车服务 |
| 工具 → 效率 | ✅ 备选 | 同上 |
| 生活服务 → 出行与交通 | ⚠️ 慎选 | 大概率要《网络预约出租汽车经营许可证》类资质 |
| 交通服务 → 共享单车/电单车 | ❌ 不要选 | 属于租赁经营，需要运营资质，你没有 |

选了租赁类目 = 审核员直接按「你有投放资质吗」问你，答不上来就驳回。

### 3. 主体 —— 个人可以，但看清楚限制

- 个人主体：能注册、能备案、能发布，**但**不能用微信支付、不能做需要资质的类目、名称审核更严
- 想长期做：建议注册个体户（成本几百块），类目和名称都会宽松很多

## 二、备案（2024 年起强制，没有它发布不了）

这是很多人漏掉的一步。**小程序也要 ICP 备案。**

路径：小程序后台 → 设置 → 基本设置 → 「小程序备案」→ 去备案

要准备：

- 主体证件（个人：身份证正反面）
- 人脸核验（微信扫脸）
- 小程序服务内容说明（写「为用户提供共享电动车投放点信息查询」，一句话）
- 负责人手机号、邮箱

耗时：一般 **1~20 个工作日**（管局审核，催不了）。

> 顺序建议：**备案和开发并行**。备案一提交，你就去弄云开发；等备案通过，代码也调通了，直接提审。

## 三、开发侧配置（约 1~2 小时）

完整步骤在 [03-部署与上线.md](03-部署与上线.md)，这里只列必做项和易漏项：

- [ ] 拿到 AppID，填进 `project.config.json` 和开发者工具
- [ ] 开通云开发，环境 ID 填进 `miniprogram/utils/config.js`（`YOUR_CLOUD_ENV_ID` 不改，全站转圈）
- [ ] 建集合 `spots`，权限设「所有用户不可读写」
- [ ] **加 `location` 地理位置索引**（类型必须选「地理位置」，选升序 = 附近功能直接报错）
- [ ] 6 个云函数全部「上传并部署：云端安装依赖」
- [ ] `spotSubmit` 超时时间改 10 秒（默认 3 秒，内容安全接口会超时）
- [ ] 跑 `spotInit` 的 `init` + `seed` 灌测试数据

### 接口权限（个人主体也能过，但要写清理由）

小程序后台 → 开发管理 → 接口设置：

| 接口 | 申请理由（直接抄） |
| --- | --- |
| `wx.getLocation` | 用户主动点击定位后，展示其周边已收录的共享电动车投放点 |
| `wx.chooseLocation` | 用户上传投放点时，在地图上选点确认具体位置 |

### 用户隐私保护指引（必填，否则位置接口调不动）

设置 → 服务内容声明 → 用户隐私保护指引，勾选：

- 位置信息 → 查找附近投放点、上传时确认位置
- 相册 → 上传现场照片（选填）
- 摄像头 → 现场拍照（选填）

代码侧已对齐：`app.json` 有 `__usePrivacyCheck__: true`，定位前会调 `wx.requirePrivacyAuthorize`。

## 四、内容合规（UGC 类小程序的审核红线）

微信对「用户能发内容」的小程序查得很细。你已经有的：

- ✅ 文本安全检测：`cloudfunctions/spotSubmit/index.js` 调 `security.msgSecCheck`
- ✅ 举报机制：`spotReport`，3 次举报自动隐藏
- ✅ 任何人可下架（避免脏数据长期挂着）
- ✅ 「关于」页有数据来源与免责说明

还需要补的（提审前做完，不然很可能被要求整改）：

- [ ] **用户协议 / 免责声明单独一页**，从「关于」能点进去。至少写：内容由用户上传、平台不保证真实性、发现错误可举报
- [ ] 「我的」页加**意见反馈**入口（已有 `feedback` 按钮，确认能拉起客服会话）
- [ ] 测试数据必须清干净：`spotInit` 的 `clearSeed`，别带着 8 条假数据去审
- [ ] 截图和介绍里不出现需资质的限定词（全国 / 中国 / 国家）

## 五、提审要准备的材料

| 材料 | 要求 |
| --- | --- |
| 小程序头像 | 144×144 以上，建议用地图 pin 图形，别用文字 |
| 服务简介 | 一句话：「帮你查附近哪里能骑到共享电单车，信息由用户共建」 |
| 截图 4~5 张 | 首页列表、地图、详情、上传页。**不要带测试数据**，文案里不要出现需资质的限定词 |
| 功能说明（补充说明栏） | 见下方模板 |
| 测试账号 | 不需要（本小程序免登录） |

补充说明模板（可直接抄进审核备注）：

```
本小程序为信息查询工具，不提供租车、支付、押金等任何交易服务。
车辆的实际租用流程由各共享电单车品牌自己的小程序提供，
用户点击「打开XX小程序」后跳转离开本小程序，交易不在本小程序内完成。

内容均由用户主动上传共建，平台已做以下措施：
1. 所有上传内容经微信内容安全接口（msgSecCheck）检测，违规不入库；
2. 每条信息提供举报入口，被举报 3 次自动隐藏并转人工复核；
3. 任何用户发现车辆已下架均可标记删除，删除即时生效。

位置权限仅用于两件事：用户主动点击定位时展示附近投放点；
用户上传时在地图上选点。不用于后台持续定位，不做轨迹记录。
```

## 六、审核被驳回常见原因对照

| 驳回理由 | 真实原因 | 怎么改 |
| --- | --- | --- |
| 名称违规 / 名称与业务不符 | 含「全国」 | 换名，见第一节 |
| 类目与实际业务不符 | 选了出行/租赁类目 | 改成「工具 → 信息查询」 |
| 涉及提供出行服务但无资质 | 简介或截图里出现「租车」「投放」太像平台自营 | 改文案：强调「信息查询」「用户共建」 |
| UGC 内容未提供管理机制 | 没写清审核/举报流程 | 补充说明里按上面模板写清楚 |
| 未配置隐私保护指引 | 位置接口没声明 | 见第三节 |
| 存在诱导分享 | 分享按钮上写了「分享给好友得…」 | 去掉激励机制，纯功能分享没问题 |
| 实际功能与截图不符 | 截图带了 seed 假数据 | 清数据后重新截图 |
