# 运营与维护

## 最值钱的一件事：补品牌 AppID

没有 AppID，用户点一下只能复制名称再去搜；有了 AppID，就是一键直达。这个差别直接决定留存。

### 怎么拿

1. 微信里打开该品牌小程序 → 右上角「…」→ **关于** → 页面上有 AppID（`wx` 开头 18 位）
2. 或让品牌方提供

### 怎么填

打开 `miniprogram/utils/brands.js`，填到对应品牌的 `appId`：

```js
{ key: 'hello', name: '哈啰出行', short: '哈啰', color: '#0091FF', appId: 'wxXXXXXXXXXXXXXX', path: '' }
```

`path` 一般留空（进目标小程序首页）。如果知道具体页面路径，可以填 `pages/index/index?id=1` 这种。

改完重新上传代码即可，不需要动数据库。

### 优先级

按你后台「被点开次数」排，先补前 5 个品牌。也可以看用户在「上传」里填了哪些 AppID —— 那是白送的线索，回填到 `brands.js` 就能全站生效。

## 内容治理

| 情况 | 处理 |
| --- | --- |
| 举报到 3 次 | 自动 `status = hidden`，不在列表展示 |
| 明显垃圾/广告 | 控制台把 `status` 改成 `rejected` |
| 内容量变大或有恶意投稿 | 把 `cloudfunctions/spotSubmit/index.js` 的 `NEED_REVIEW` 改 `true`，全部进人工审核 |
| 城市已无该品牌投放 | 直接删文档，或改 `rejected` 保留记录 |

### 每周花 5 分钟做的事

1. 控制台 → 数据库 → `spots` → 筛选 `reportCount >= 3`，看被下架的
2. 筛选 `status = 'pending'`（如果你开了审核）
3. 看一眼云函数调用次数和数据库读写量，判断有没有异常刷

## 示例数据清理

上线前一定执行，否则用户会看到「深圳科技园有美团电单车」这种不存在的投放点：

云函数 `spotInit` → 云端测试 → `{ "action": "clearSeed" }`

`seeded: true` 的都会被删，真实用户数据不受影响。

## 成本

云开发基础版 1 的免费额度（每月）大致覆盖：云函数调用 20 万次、数据库读写 5 万次、存储 5GB。

按日活 500 人估算（每人 3 次云函数调用）≈ 每月 4.5 万次，远在免费额度内。

真正会涨的是：**图片存储**。3 张/条，一条 300KB 左右。如果在意成本，可以把上传入口的图片改成选填提示「不上传也能提交」，或者上传时压缩（代码里已用 `sizeType: ['compressed']`）。

## 数据备份

云开发控制台 → 数据库 → `spots` → 导出（JSON）。建议每月导一次到本地。

代码侧：整个工程 `git init` 一份，`project.private.config.json` 和云函数 `node_modules` 加进 `.gitignore`。
